Plan de Contingencia
1. Propósito
Este Plan de Contingencia define los pasos a seguir cuando ocurran problemas o situaciones especiales que impidan usar con normalidad el sistema de asistencia. Su meta es asegurar que todos los aprendices puedan registrar su llegada sin interrumpir la clase ni afectar la jornada de formación.

2. Casos de contingencia
Caso 1. Aprendiz sin teléfono móvil
Situación:
El aprendiz no tiene un celular a la mano para leer el código QR.

Acción de contingencia:
El instructor anotará la asistencia de forma manual desde el panel de control del sistema.

Caso 2. Aprendiz con discapacidad visual
Situación:
El aprendiz tiene una dificultad visual que le impide manejar la aplicación por sí solo.

Acción de contingencia:
El instructor le ayudará durante el proceso o hará el registro de manera manual si hace falta.

Caso 3. Aprendiz con discapacidad auditiva
Situación:
El aprendiz tiene una discapacidad auditiva.

Acción de contingencia:
La plataforma mostrará avisos visuales fáciles de entender y el instructor le dará apoyo en persona si lo necesita.

Caso 4. Aprendiz con discapacidad motriz
Situación:
El aprendiz tiene dificultades físicas para usar el celular.

Acción de contingencia:
El instructor se encargará de registrar su asistencia manualmente.

Caso 5. Falla del código QR
Situación:
El código QR no carga bien en pantalla o la cámara no logra leerlo.

Acción de contingencia:
El instructor creará un nuevo código QR. Si la falla sigue, pasará a hacer el registro manual.

Caso 6. Código de verificación incorrecto o vencido
Situación:
El código que escribe el aprendiz está mal o ya se venció el tiempo para usarlo.

Acción de contingencia:
El sistema creará un código nuevo para que el aprendiz vuelva a escribirlo.

Caso 7. Falta de conexión a Internet
Situación:
Se cae el Internet o no hay señal en el momento de tomar la asistencia.

Acción de contingencia:
El instructor llevará el control en una lista manual por el momento y subirá los datos al sistema apenas regrese la conexión.

Caso 8. Aprendiz no registrado
Situación:
Los datos del aprendiz todavía no aparecen en la base de datos del programa.

Acción de contingencia:
El sistema pedirá estos datos básicos:

Nombre completo.

Tipo de documento.

Número de documento.

Luego guardará al aprendiz en el sistema y marcará su asistencia de inmediato.

Caso 9. Registro duplicado
Situación:
El aprendiz trata de marcar su asistencia más de una vez en la misma clase o jornada.

Acción de contingencia:
El sistema rechazará el segundo intento y mostrará un aviso explicando que su asistencia ya quedó guardada.

3. Responsables
Instructor
Abrir la sesión de asistencia al iniciar la clase.

Poner en marcha estas soluciones cuando ocurra algún problema.

Anotar de forma manual a los aprendices en casos especiales.

Revisar que nadie quede por fuera de la lista.

Aprendiz
Marcar su asistencia escaneando el QR y escribiendo el código de seguridad.

Avisar a tiempo si tiene algún problema técnico o personal para registrarse.

Sistema
Crear el código QR y el código de seguridad sin errores.

Comprobar los datos del aprendiz.

Impedir que una persona quede anotada dos veces el mismo día.

Guardar los datos de forma segura.

Mostrar mensajes claros cuando ocurra algún fallo.

5. Objetivo del plan
Lograr que el control de asistencia siga funcionando sin importar los inconvenientes que se presenten. Así se asegura que ningún aprendiz pierda su registro por fallas técnicas, falta de celular o condiciones especiales, cuidando siempre que los datos guardados sean reales y seguros.
